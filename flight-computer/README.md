# PSI 비행 컴퓨터

Arduino Portenta H7용 로켓 비행 펌웨어다. M7은 센서 수집, 상태 추정,
발사·전개·착지 판단과 서보 제어를 담당한다. M4는 M7에서 받은 데이터를
SD카드에 기록하고 XBee로 지상국에 보낸다.

| 코어 | 소스 | 실행 주기 |
|---|---|---|
| M7 | `src/m7/main_m7.cpp` | 비행 루프 100Hz, UKF는 새 기압 샘플마다 약 50Hz |
| M4 | `src/m4/main_m4.cpp` | 수신 데이터 SD 기록, XBee 송신 25Hz |

기존 단일코어 펌웨어는 [`legacy/`](legacy/README.md)에 있다.
현재 프로젝트를 빌드할 때는 포함되지 않는다.

## 하드웨어 연결

| 장치 | 연결 | 펌웨어가 사용하는 설정 |
|---|---|---|
| EBIMU-9DOFV6 | UART PJ_8 / PJ_9 | 230400 baud, 12필드 ASCII, 100Hz |
| NEO-M9N | UART PG_14 / PG_9 | 38400 baud, UBX-NAV-POSLLH, 25Hz |
| BMP390 | Wire2, I2C 주소 `0x76` | 기압 ×8, 온도 오버샘플링 없음, IIR 계수 3, 50Hz |
| 낙하산 서보 | D2 | 0° 개방, 120° 잠금 |
| XBee | Serial1 | 115200 baud, M4에서 사용 |
| microSD | Breakout 보드 SDMMC 슬롯 | M4에서 사용 |

IMU와 GNSS의 출력 설정은 센서에 미리 저장되어 있어야 한다. 비행 펌웨어는
부팅 때 출력 형식을 설정하지 않는다. IMU 설정과 복구 방법은
[IMU 설정 문서](docs/IMU_EBIMU_CONFIG.md)를 참고한다.

기울기 판정은 기수가 위를 향할 때 `cos(roll) × cos(pitch)`가 약 −1인
장착 방향을 전제로 한다. 센서나 서보 장착을 바꾸면 각도와 개방 방향을
다시 확인해야 한다.

## 1. 빌드

이 문서의 명령은 `flight-computer/`에서 실행한다. PlatformIO가 필요하며,
플랫폼과 프레임워크 버전은 `platformio.ini`에 고정되어 있다.

```bash
pio run
```

결과물은 `.pio/build/portenta_h7_m7/firmware.bin`과
`.pio/build/portenta_h7_m4/firmware.bin`이다. 라이브러리는 `lib/`에 포함되어
있다. BMP3XX 드라이버에는 `setupNormalMode()`와 `readNonBlocking()`이
추가되어 있으므로 원본 라이브러리로 교체하면 현재 코드를 빌드할 수 없다.

## 2. 업로드

**M4를 먼저 올리고 M7을 나중에 올린다.** M7의 `RPC.begin()`이 M4를 부팅한다.

```bash
pio run -e portenta_h7_m4 -t upload
pio run -e portenta_h7_m7 -t upload
```

자동 업로드가 포트 오류로 실패하면 RESET 버튼을 두 번 눌러 DFU 모드로
진입한 뒤 `dfu-util`로 업로드할 수 있다. 아래 주소는 현재 보드 설정의
플래시 시작 주소다.

```bash
dfu-util -l
dfu-util -d 0x2341:0x035b -a 0 -s 0x08100000 -D .pio/build/portenta_h7_m4/firmware.bin
dfu-util -d 0x2341:0x035b -a 0 -s 0x08040000:leave -D .pio/build/portenta_h7_m7/firmware.bin
```

부팅 중 서보가 움직인다. 장착된 분리 장치가 작동할 수 있으므로 전원을
넣기 전에 시험 구성을 확인한다.

## 3. 부팅과 캘리브레이션

```bash
pio device monitor -b 115200
```

M7은 RPC 연결과 송신 스레드를 시작한 뒤 센서를 확인한다. 기압계 초기화는
최대 10초 동안 재시도하고, IMU와 GNSS는 2초 동안 수신 상태를 확인한다.
이후 다음 순서로 준비한다.

1. 서보를 잠금 → 개방 → 잠금 순서로 움직인다.
2. IMU가 응답하면 자이로 영점 보정과 위치 초기화를 수행한다. 자이로 보정
   중에는 정지 상태를 유지한다. 이어지는 15초 자기계 보정 구간에는 로그
   안내에 따라 센서를 여러 방향으로 회전한다.
3. 기압계가 응답하면 6초 동안 기준기압을 측정한다. 이때 기체를 정지시킨다.
4. 미션 시계를 시작하고 `PRELAUNCH`로 전환한다.

기준기압은 정상 모드 설정 성공, 유효 샘플 200개 이상, 거부 샘플 20개 이하,
최대·최소 차이 0.5hPa 이하일 때 사용할 수 있다. 실패하면 고도 발사 판단과
속도 전개 경로가 비활성화된다.

RPC 초기화나 송신 스레드 시작에 실패하면 빨간 LED를 점멸하며 부팅을
멈춘다. IMU와 기준기압을 모두 사용할 수 없으면 발사를 감지할 수 없다.
14초 강제 전개 타이머도 발사가 감지된 뒤에만 시작한다.

## 4. 텔레메트리

지상국 실행 방법은 [저장소 README](../README.md#run-the-ground-station)에 있다.
XBee 프레임은 총 92바이트이며, payload는 little-endian이다.

```text
0x7E | state (1 byte) | float32 × 22 | health (1 byte) | 0x0A
```

float 필드 순서는 `time`, `lat`, `lon`, `euler[3]`, `accel[3]`, `gyro[3]`,
`pos[3]`, `altitude`, `pressure`, `kalman[4]`, `gnssAlt`다.
시간은 미션 시작 후 ms, 기압은 hPa, 고도는 m다. `kalman[4]`에는 추정 고도,
수직속도, 예측 정점고도, 회귀 적합도 R²가 들어간다.

상태 바이트는 `0xBA` PRELAUNCH, `0xBB` LAUNCH, `0xBC` DEPLOY,
`0xBD` LANDED다. 지상국은 마지막 상태를 GROUND로 표시한다.
텍스트 로그는 `0xAA` 접두 바이트와 CRLF로 구분한다.

| Health 비트 | 의미 |
|---|---|
| `0x01` | IMU 데이터가 30ms 이내 |
| `0x02` | 기압 데이터가 60ms 이내 |
| `0x04` | IMU가 500ms 내에 응답 |
| `0x08` | 기압계가 500ms 내에 응답 |
| `0x10` | 유효 GNSS 프레임을 1초 내에 수신 |
| `0x20` | 기준기압 품질검사 통과 |
| `0x40` | 속도 전개 경로가 영구 차단되지 않음 |
| `0x80` | 현재 속도 전개 입력을 사용할 수 있음 |

`0x80`은 발사 여부나 5초 전개 잠금을 나타내는 비트가 아니다.
GNSS 응답 비트도 위치 fix를 보장하지 않는다.

## 5. SD 기록

M4는 부팅마다 사용하지 않은 번호를 찾아 `flight_NNN.csv`와
`flight_NNN.txt`를 만든다. CSV에는 수신한 텔레메트리를, TXT에는 센서 초기화,
캘리브레이션과 상태 전환 메시지를 기록한다. 000부터 999까지 모두 사용하면
새 기록을 시작하지 않는다.

CSV의 `time_ms`와 M7 텍스트 로그의 `[ms]`는 같은 미션 시계를 사용한다.
부팅 로그는 미션 시계가 시작되기 전의 시간을 사용하며,
`[ZERO] mission clock start`가 경계를 표시한다. M4 자체 메시지는 `[M4 ms]`로
구분한다.

마지막 `note` 열은 health 비트를 풀어 쓴 값이다. 여러 상태는 `|`로 이어진다.

| Note | 의미 |
|---|---|
| `ok` | 모든 health 비트가 설정됨 |
| `imu_stale`, `baro_stale` | 센서는 응답하지만 데이터가 제어 유효기간을 넘김 |
| `imu_dead`, `baro_dead`, `gnss_dead` | 센서 응답 시간 초과 |
| `no_baro_ref` | 유효한 기준기압 없음 |
| `vz_settle` | 속도 경로는 유지되지만 현재 입력을 사용할 수 없음 |
| `vz_off` | 속도 전개 경로 차단 |

센서가 끊겨도 마지막 측정값은 남아 있을 수 있다. 지상국의 SD 로그 재생은
측정값 존재 여부 대신 이 note를 읽어 상태를 표시한다.

SD 쓰기는 별도 스레드에서 수행하고 200ms 간격으로 flush와 fsync를 시도한다.
쓰기 오류가 연속 세 번 발생하면 기록을 중단하고 XBee로 알린다. 버퍼가 차면
데이터가 유실될 수 있고, 실패한 쓰기를 재시도하는 과정에서 CSV 행이 중복될
수 있다. LANDED 전환 때 출력되는 비행 요약의 drop 카운터와 시간을 함께 확인한다.

## 6. 동작 원리

### 6.1 실행 구조

M7 루프는 GNSS·IMU·기압 수집, UKF 갱신, 센서 상태 갱신, 비행 판단,
텔레메트리 큐 적재 순서로 실행된다. 10ms 마감 시각을 놓치면 지나간 주기를
건너뛴다. RPC 쓰기와 USB 로그 출력은 별도 송신 스레드가 담당한다.

### 6.2 데이터 흐름

UKF는 IMU의 전역 Z축 가속도와 기압고도를 입력으로 사용한다. GNSS 위치와
해수면고도, IMU 적분 위치는 기록·회수용이며 비행 판단에는 사용하지 않는다.
기압고도는 부팅 때 정한 기준기압에 대한 상대 높이다.

### 6.3 센서 입력

IMU는 `*roll,pitch,yaw,gx,gy,gz,ax,ay,az,dx,dy,dz` 형식의 12필드만 받는다.
숫자 형식, 유한값, 자세·각속도·가속도 범위를 확인한 뒤 갱신한다.

기압은 300–1250hPa 범위를 확인한다. 직전 유효 샘플과 200ms 이내라면
고도 변화율도 검사한다. 새 샘플이 없으면 기존 값으로 UKF를 다시 계산하지 않는다.

GNSS는 체크섬이 맞는 UBX-NAV-POSLLH 프레임을 받는다. 수평 정확도가
100m 이내이고 위도·경도 범위가 유효할 때 위치를 갱신한다. POSLLH에는
fix 유효 플래그가 없으므로 이 조건만으로 항법용 위치를 보장할 수는 없다.

### 6.4 데이터 유효기간

제어 입력 유효기간과 센서 응답 시간 초과는 별개다. IMU 30ms, 기압 60ms를
넘은 값은 해당 제어 투표에 사용하지 않는다. 센서 응답 여부는 더 긴
IMU·기압 500ms, GNSS 1000ms 기준으로 판단한다.

### 6.5 상태 추정

UKF의 시간 간격은 0.02초로 고정되어 있다. IMU의 중력 제거 가속도(g)를
m/s²로 바꾸고 중력항을 더해 필터에 넣는다. 출력 수직속도는 위쪽이 양수다.

기압 간격 100개의 평균이 17.5–22.5ms에 들어오면 속도 경로의 주기 조건을
통과한다. 이후에도 50개 간격마다 평균을 확인한다. 35ms보다 긴 공백이나
최근 네 정상 간격의 합이 70–90ms 범위를 벗어나면 속도 입력을 500ms 동안 막는다.

### 6.6 투표 창

발사와 전개는 한 번의 측정으로 판단하지 않는다. 각 조건이 최근 N회 중
몇 회 참이었는지 센다. 모든 투표는 100Hz 루프에서 갱신되므로 루프가
지연되면 실제 판단 시간도 길어진다.

### 6.7 비행 상태 전환

PRELAUNCH에서는 수직 가속도 절댓값이 2g를 넘는 표가 20회 중 12회이거나,
최근 두 기압 샘플의 평균 고도가 10m를 넘는 표가 40회 중 24회이면 LAUNCH로
전환한다. 고도 경로에는 유효한 기준기압이 필요하다.

발사 감지 뒤 **5초 동안 모든 전개 경로를 잠근다.** 잠금이 풀리면 아래
순서로 판단한다. 14초 타이머는 센서 경로와 별도로 평가한다.

| 경로 | 조건 |
|---|---|
| 속도 | 사용 가능한 추정 수직속도가 −7m/s 미만인 표가 12회 중 7회 |
| 기울기 백업 | 속도 경로가 비활성이고 IMU가 유효할 때, `cos(roll) × cos(pitch) > 0.70711`인 표가 25회 중 15회 |
| 강제 타이머 | 발사 감지 후 14초 초과 |

속도 경로가 선택되어 있으면 기울기 표는 쌓이지 않는다. 다만 잠금 해제 후
속도 입력을 **1000ms 연속 사용할 수 없으면** 속도 경로를 영구 차단하여
기울기 백업을 허용한다. 중간에 입력이 사용 가능해지면 이 연속 시간은
초기화된다. 짧은 공백은 복구를 기다리고, 지속적인 저하는 백업으로 넘긴다.

DEPLOY에 들어가면 서보를 먼저 연다. 1초 동안 개방한 뒤 착지하지 않았으면
500ms 잠갔다 다시 여는 동작을 반복한다. 잠금 중 루프가 지연될 경우를 위해
600ms 후 개방하는 타이머도 설정한다.

착지는 자이로 벡터 크기 5dps 이하, 가속도 벡터 크기 0.2g 이하인 정적
상태가 최근 2500회 중 1500회 누적될 때 판단한다. 기준 고도에서 2m를 벗어나면
투표를 초기화한다. LANDED 전환은 서보가 열린 상태에서만 수행한다.

### 6.8 센서 고장 시 동작

비행 중 기압 공백이 200ms를 넘거나 IMU 응답이 끊기면 속도 경로를 영구
차단한다. IMU가 복구되어도 속도 경로는 다시 켜지지 않고 기울기 백업만
사용할 수 있다. IMU도 사용할 수 없으면 강제 타이머만 남는다.

착지 판단에서는 IMU가 응답하지 않으면 움직임이 없는 것으로 취급한다.
기압계까지 끊기면 고도도 고정되므로, 이 경우의 LANDED 표시는 실제 착지를
확인한 결과가 아니다. 서보 재시도 종료 여부를 해석할 때 구분해야 한다.

### 6.9 설정 위치

주기, 임계값, 투표 수와 시간 제한은 `main_m7.cpp`의 `[4] Parameters`에 있다.
서보 각도는 `[2] Sensor Mapping`, 송신 간격은 M4의 `TELEM_DECIMATE`에서 정한다.
현재 값은 4로, 수신 데이터 네 개마다 한 프레임을 XBee로 보낸다.

### 6.10 코어 간 통신

IPC 프레임은 시작 바이트 `0xA5`, 타입, 2바이트 길이, payload, XOR 체크섬으로
구성된다. M4는 체크섬이 맞는 프레임만 처리한다. M7 송신 큐가 차면
비행 루프를 대기시키지 않고 프레임을 버린 뒤 누락 횟수를 기록한다.

### 6.11 유지보수

비행 루프에 RPC·SD·USB 출력을 직접 추가하지 않는다. 센서 수집 경로에도
시간이 제한되지 않은 대기가 들어가지 않도록 확인한다. 강제 전개 타이머는
루프가 실행되는 동안에만 평가된다.

패킷을 바꿀 때는 `src/shared/telemetry_frame.h`와 지상국의 수신 형식을 함께
수정한다. 서보 동작, 센서 설정, 전개 임계값 변경은 실제 장착 상태에서
확인해야 한다. 빌드 성공만으로 장치 동작이나 비행 적합성을 판단하지 않는다.

## 문제 확인

| 증상 또는 로그 | 확인할 항목 |
